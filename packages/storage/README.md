# Local persistence

`src/index.ts` owns version1 preference/history/layout sanitation, ordering and serialized storage writes. Failed worker writes preserve prior visible choices; invalid serialized records are not silently reset. The worker uses one `createPreferencesStore` for load/save through the supported get/set storage bridge. `patchPreferences` merges editable choices for both worker and fixture preview, preserving unrelated UI settings and confirmed history. Preference-file import/export, reset and bridge removal have no supported entry point. Defaults are created per caller. Legacy identifiers remain readable but grant no navigation/audio authority. `src/guide-cache.ts` stores sanitized listing metadata without watch targets, with bounded optional retries/counters. [Domain tests](../../tests/domain.test.ts) and [guide-cache tests](../../tests/guide-cache.test.ts) cover synthetic records; [failure recovery](../../docs/ERROR_HANDLING.md) describes limits.

`sanitizeWorkspaceLayout` owns the additive `yttv-desktop.workspace-layout.v1` record. It allowlists layout modes and optional normalized custom rectangles keyed by show count (1–4), while keeping legacy Auto/Top-bottom records readable. It stores no player, URL or audio authority and leaves the existing area and version 1 preference schemas unchanged. The worker serializes its writes with workspace mutations.
