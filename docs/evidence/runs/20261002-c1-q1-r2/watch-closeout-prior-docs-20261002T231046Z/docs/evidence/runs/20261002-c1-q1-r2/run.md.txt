## Repair and safety contract

A separate local v1 metadata cache retains only channel ID/name, original row observation timestamp, observed row order and bounded program/next text. At most 500 rows; conservative character limit bounds serialized UTF-8 to 512,000 bytes. URLs, targets, target verification timestamps, arbitrary fields and session/tab/window authority are excluded by reconstruction. Cache reads never write or renew observation age. Program text older than 24 hours is discarded; valid channel identities/order remain visible and unavailable. Missing/malformed/duplicate/future-dated/unsupported/oversized data yields an empty optional cache. Read/write failure preserves playback and native Live fallback. Preferences have a separate key; failed preference reads cannot overwrite retained values with defaults.

Cached rows are explicitly marked CACHED, unavailable, target null. Fresh Live metadata replaces applicable older rows; missing/unavailable rows keep their position. Captured sanitized revisions use a serialized write queue; older delayed observations cannot overwrite newer metadata. Ordinary Watch observations and fixture data do not update the persistent cache. Volatile freshly validated handles remain confined to the existing runtime adapter path.

Watch displays saved last-confirmed history separately from newly observed advancing playback. Favorites/recents remain understandable, including saved identity placeholders if metadata is missing. Previous/Watch/Add require the specific fresh target. Restoring saved Current/history does not itself confirm a switch. Guide labels and footer use guide observation timestamps, rather than the current page observation time. Explicit **Open native Live** recovery navigates only the designated existing tab after a user action; cache restoration never changes channel or opens another feed. Browser routing lives in the bridge; selectors remain in the adapter.
